# 设计与完成条件

## 完成条件

1. 单篇：原始微信页面存在可解析的标题和非空文字正文；不是验证、登录或删除提示。完整读取响应，不设固定正文截断长度。
2. 原文输出：Markdown、纯文本、JSON 均写入成功，保留原链接、公众号、发布时间和图片位置。
3. 历史发现：按名称唯一匹配账号；遍历来源提供的分页，不能把接口失败当成空列表。
4. 批量归档：清单中的所有原文均已保存；否则 `archive_complete=false`。
5. 覆盖范围：当前来源末页不等于公众号全部历史；`global_history_complete` 不由本工具推断为真。
6. 发布：测试和打包通过；GitHub 仓库只含代码、人工测试数据与文档，不含登录状态、抓取的文章正文或私人路径。

## 数据路径

首次启动：`wechat-archive start 名称` 或无参数启动 → 检查现有登录 → 必要时打开本机二维码窗口 → 手机微信授权微信读书 → 再次检查连接 → 继续原任务。有效登录不重复扫码；取消、过期或失败不进入抓取。

扫码页面仅监听 127.0.0.1 的随机端口，路径使用临时随机值，页面不含登录凭据。二维码在内存中生成，登录结束后清除。外部 SDK 通过结构化事件提供二维码和状态；身份、accessToken、refreshToken 不传递到页面或程序输出。启动参数 `--no-login`、机器读取模式 `--json` 会禁用自动登录。

网络失败、频率限制、人工验证与登录失效是不同状态。只有登录失效会启动扫码，其他错误保留原因并停止。扫码登录成功不等于搜索和历史接口一定可访问。

```text
原文链接 → 链接校验 → 微信公开原页面 → js_content → Markdown / text / JSON

公众号名称 → 当前来源搜索 → 精确选择账号 → 逐页历史 → 原文链接清单
                                                     ↓
                                 去重与文件核对 → 微信原文读取 → 更新完成状态
```

默认历史来源：`weread-omni@0.1.2` 的个人微信读书登录。搜索使用 scope=2，首个历史请求省略 offset，后续只使用 nextOffset，绝不用 synckey 当页码。清单里的原文链接优先取 mpInfo.doc_url；缺失时读取 review single。不会把不透明的 originalId 直接拼成文章链接。

后台来源：只读取 searchbiz 和 appmsgpublish，不创建草稿、不发送消息。发布批次内可能包含多篇文章，因此发布记录总数和文章总数是两种数量。

## 不完整、失败与恢复

- 原页面没有正文：抛出明确异常，不生成空文章。
- 内容只有图片：当前版本不提供 OCR，报告无法提取文字正文。
- 后台数据层级损坏：停止枚举，保留已发现链接，不跳过异常记录后声称完整。
- 页数达到上限、重复页、分页位置不推进：历史列表未完成。
- 后台总记录数在同一轮中变化：停止并要求重跑核对；数值分页不具备服务端快照保证。
- 微信读书返回下一页：必须继续；声称有更多但缺少游标时停止并报告结构异常。
- 文章访问触发验证：停止继续下载，保留未完成项。
- 普通删除页或个别读取失败：记录到该链接，其他可读文章仍可保存。
- 重新运行：从列表头部开始重新核对，但复用已经校验过的正文文件。不会直接从旧数字页码继续，避免新发布使旧页码失效。

每轮先发现列表，再下载正文。若列表阶段受限中断，本轮只保留已发现清单；处理限制后重跑。文件写入使用同目录临时文件加替换。单个账号输出不支持多个进程同时写入。

## 可验证性与安全边界

- 公众号名、发布时间来自微信原页面，文本不从转载补齐。
- 正文 SHA-256 保存在 JSON 和账号清单；恢复时核对三种文件及正文校验值。
- 所有下载正文的请求只发送到 HTTPS mp.weixin.qq.com。外站跳转停止。
- 后台 Cookie 与公共原文请求分属两个会话，不向原文下载客户端传后台凭据。
- 历史凭据只保存在本机配置目录。程序错误不打印 Cookie、token 或上游原始错误响应。
- 只接收当前登录允许读取的列表，不提供验证码求解、权限绕过或被删除内容恢复。
- Markdown 中的图片来自原文在线地址；本版本不缓存图片、音视频和评论。

## 已知不确定性

微信读书能搜到的公众号集合、历史条数和非公开接口稳定性由平台决定。本项目没有平台全量清单可用于核实其覆盖率，因此即使来源末页与全部正文已取得，也只能证明“该来源本轮提供的列表已遍历”。
